# Курс 0. Основа: вайбкодинг и нейросети с нуля

**Длительность:** 4 недели · **Нагрузка:** 4–6 ч/неделя · **Уровень:** с нуля
**Результат:** ученик уверенно пишет промпты, понимает, как работают нейросети, и собирает и публикует свой первый рабочий мини-проект с помощью ИИ-агента без ручного программирования.

## Для кого
Новички без опыта. Обязательная база для всех остальных курсов.

## Что умеет выпускник
- Объяснить простым языком, что такое LLM, токены, контекст, галлюцинации
- Писать структурные промпты и итеративно улучшать результат
- Подбирать нейросеть под задачу (текст, код, картинки, видео, звук)
- Собрать и запустить простой проект «вайбкодингом»
- Использовать Git/GitHub на базовом уровне и опубликовать результат
- Безопасно работать с ИИ (данные, ключи, авторские права)

---

## Неделя 1. Как думают нейросети и как с ними говорить

**Цель недели:** понять принципы и научиться получать нужный ответ с первой–третьей попытки.

| Урок | Тема | Практика |
|---|---|---|
| 1.1 | Карта нейросетей: текст, изображения, видео, звук, агенты. Что умеет и не умеет ИИ | Завести аккаунты, пройти чек-лист безопасности |
| 1.2 | Как работает LLM: токены, контекст, температура, галлюцинации | 3 эксперимента с одним вопросом и разными настройками |
| 1.3 | Анатомия промпта: роль, контекст, задача, формат, ограничения, примеры | Переписать 5 слабых промптов в сильные |
| 1.4 | Итерации и уточнения; цепочки промптов; «попроси ИИ задать вопросы» | Довести текст/задачу до результата за 3 итерации |
| 1.5 | Проверка фактов и защита от галлюцинаций | Найти 3 ошибки в ответе ИИ |
| 1.6 | Личная база промптов и «системные инструкции» | Собрать свою библиотеку из 10 промптов |

**ДЗ недели 1:** решить 3 реальные рабочие/жизненные задачи через ИИ и приложить промпты + результат.

## Неделя 2. Вайбкодинг: первый проект за вечер

**Цель недели:** собрать работающее приложение без написания кода вручную.

| Урок | Тема | Практика |
|---|---|---|
| 2.1 | Что такое вайбкодинг: идея, границы, где ломается | Разбор примеров удачных и неудачных проектов |
| 2.2 | Инструменты: ИИ-редактор кода/агент, браузерные конструкторы | Установить и настроить рабочее окружение |
| 2.3 | Как ставить задачу агенту: ТЗ, критерии готовности, маленькие шаги | Написать ТЗ на мини-проект |
| 2.4 | Первый проект: трекер привычек / калькулятор / визитка (на выбор) | Собрать проект по шагам |
| 2.5 | Как читать сообщения об ошибках и просить ИИ исправить | 5 намеренно сломанных проектов — починить |
| 2.6 | Как понимать, что сгенерировано (минимальный «код-грамотность») | Разметить чужой файл: что за что отвечает |

**ДЗ недели 2:** работающий мини-проект + краткое описание, что делал и где застревал.

## Неделя 3. Проект, Git и данные

**Цель недели:** довести проект до состояния «показать людям» и научиться сохранять версии.

| Урок | Тема | Практика |
|---|---|---|
| 3.1 | Git и GitHub для нефанатов: коммиты, ветки, откат | Создать репозиторий, сделать 5 коммитов, откатиться |
| 3.2 | Структура проекта, README, шаблоны | Оформить README проекта |
| 3.3 | Данные: формы, хранение, простая база | Добавить сохранение данных |
| 3.4 | Внешние сервисы и API-ключи; безопасность секретов | Подключить один внешний сервис безопасно |
| 3.5 | Тестирование «на человеке»: сценарии проверки, баги | Составить чек-лист и пройти по нему |
| 3.6 | Когда ИИ «зациклился»: как выходить из тупика (перезапуск контекста, разбиение задачи) | Разобрать 3 кейса |

**ДЗ недели 3:** проект в GitHub с README и историей коммитов.

## Неделя 4. Публикация и финальный проект

**Цель недели:** выпустить проект в интернет и подготовить кейс в портфолио.

| Урок | Тема | Практика |
|---|---|---|
| 4.1 | Публикация: бесплатный хостинг, домен, HTTPS | Опубликовать проект |
| 4.2 | Улучшение внешнего вида с помощью ИИ: цвета, шрифты, макет | Редизайн проекта |
| 4.3 | Юридическая и этическая гигиена: данные пользователей, лицензии, авторские права на материалы ИИ | Чек-лист проекта |
| 4.4 | Как учиться дальше: карта следующих курсов, источники обновлений | Выбрать свою траекторию |
| 4.5 | Защита финального проекта | Короткая презентация (3 мин) |

**Финальный проект:** опубликованное приложение/страница с описанием: проблема → решение → промпты → ссылка.

### Критерии зачёта
- Проект открывается по ссылке и работает
- Есть README и история коммитов
- Ученик может объяснить, что делает каждая часть на верхнем уровне
- Нет утёкших ключей и личных данных

### Материалы
Библиотека промптов, шаблоны проектов, чек-лист безопасности, шпаргалка по ошибкам, глоссарий терминов.

### Куратор
Проверка ДЗ (по тарифу), ответы в чате в течение 24 часов, эфир по воскресеньям.
